# v4 新 Y 设计：自然人责任边界与企业风险披露可核验性

生成日期：2026-05-06

## 1. 一句话判断

v3 的 Y 不能直接搬到 v4，但 v3 的构造思想可以搬：

```text
从“泛披露强度”转向“可被外部证据核验的披露结构”。
```

v4 的新 Y 应该是：

```text
可核验风险披露
```

更具体地说：

```text
企业风险披露中是否出现具体责任主体、债务追偿、担保、质押、诉讼、
逾期、违约、冻结、执行、金额、期限等可外部交叉验证的信息。
```

这个 Y 比单纯 `risk_quality_index` 更贴合“自然人责任边界”。

## 2. 研究设计中的位置

建议研究问题写成：

```text
当本地个人破产制度或个人债务集中清理机制出现后，
原先企业风险与自然人责任高度绑定的企业，
是否会减少空泛、模板化风险叙事，
增加更具体、可核验的责任风险披露？
```

DDD：

```text
PB_city,t × PreNaturalPersonLiabilityExposure_i
-> VerifiableRiskDisclosure_i,t
```

不要写成：

```text
PB -> 风险披露质量提高
```

更稳的是：

```text
PB 改变自然人责任边界和债权追偿预期，
使高自然人责任/高债务追偿暴露企业的风险披露从模板化风险叙事
转向更具体、可核验的责任风险表达。
```

## 3. 和现有 v4 指标的关系

现有风险披露指标来自：

```text
risk_disclosure_trial/extract_risk_disclosure_features.py
risk_disclosure_trial/risk_disclosure_features_2015_2023.parquet
```

已有指标：

```text
has_risk_text
risk_chars_ln
risk_specificity_index
risk_quality_index
risk_boilerplate_ratio
risk_debt_per10k
risk_category_count
```

这些可以保留，但新 Y 应该分层：

```text
L0: has_risk_text / risk_chars_ln
    是否披露风险、披露长度。

L1: risk_specificity_index / risk_quality_index
    一般风险披露具体性。

L2: risk_verif_no_policy_kw / risk_verif_no_policy_share
    剔除政策名词后的通用可核验风险披露。

L3: np_liability_risk_verif_kw / np_liability_risk_verif_share
    更贴自然人责任边界的责任风险可核验披露。

L4: external validation
    自然人担保、股权质押、诉讼仲裁、债务逾期、冻结执行、信用减值等真实事件验证。
```

主文更适合用 L2/L3，L0/L1 作为对照。

## 4. 抽取范围

建议只在已抽出的风险披露段中计数，不在年报全文计数。

理由：

1. 全文里“担保、诉讼、质押、冻结”等词可能出现在附注、公司治理、重大事项中，不一定是风险披露；
2. 本文的 Y 是“风险披露可核验性”，不是企业实际风险事件；
3. 现有 `risk_disclosure_features_2015_2023.parquet` 已经有风险段文本预览和风险段识别逻辑，可以在这个基础上升级。

如果后续实现需要更精确，应保留完整风险段文本，而不只保留 `risk_preview`。

## 5. 政策名词屏蔽

仿照 v3 的 no-institution Y，v4 应先屏蔽政策名词，避免机械相关。

屏蔽词建议：

```text
个人破产
个人破产制度
个人破产试点
个人债务集中清理
债务集中清理
自然人破产
破产试点
破产保护
```

屏蔽后再计数。否则政策试点城市企业在风险披露中提到“个人破产制度”，会被误当成可核验风险披露。

## 6. 新 Y 变量设计

### 6.1 通用可核验风险披露

变量名：

```text
risk_verif_no_policy_raw
risk_verif_no_policy_per10k
risk_verif_no_policy_share
```

含义：

```text
风险段中出现可被外部证据核验的具体风险信息。
```

关键词组件：

```text
金额数字:
万元、亿元、金额、余额、比例、占比、利率、期限、到期、报告期末

责任主体:
客户、供应商、银行、金融机构、债权人、债务人、担保方、保证人、关联方

债务风险:
债务、偿债、融资、授信、银行贷款、借款、现金流、流动性风险、资金链

违约逾期:
违约、逾期、展期、延期支付、无法偿还、不能按期偿付、债务重组

法律程序:
诉讼、仲裁、判决、裁定、执行、强制执行、查封、冻结、保全、被申请执行

担保质押:
担保、保证、连带责任、反担保、抵押、质押、股权质押、担保物、抵质押物
```

建议不要只做一个黑箱总指数，至少保留组件。

### 6.2 自然人责任风险可核验披露

变量名：

```text
np_liability_risk_verif_raw
np_liability_risk_verif_per10k
np_liability_risk_verif_share
```

含义：

```text
风险段中直接涉及自然人责任、个人担保、自然人控制人、自然人追偿价值的信息。
```

关键词建议：

```text
自然人责任主体:
实际控制人、实控人、控股股东、法定代表人、董事长、总经理、
董监高、管理层、自然人股东、个人、配偶、亲属

个人责任方式:
个人担保、个人保证、连带保证、连带责任、无限连带责任、
个人连带责任、个人反担保、共同担保

追偿与履约:
追偿、代偿、清偿、偿付、履约能力、偿债能力、资产状况、
信用状况、财产线索

控制权风险:
股权质押、股份质押、平仓、补仓、控制权稳定、控制权变更、
表决权、司法冻结
```

这组变量才是最贴“自然人责任边界”的主 Y。

### 6.3 组件变量

建议至少构造：

```text
risk_legal_process_kw
risk_guarantee_pledge_kw
risk_debt_distress_kw
risk_named_counterparty_kw
risk_amount_deadline_kw
risk_np_person_kw
risk_np_guarantee_kw
risk_controller_pledge_kw
```

其中：

```text
risk_guarantee_pledge_kw
risk_np_guarantee_kw
risk_controller_pledge_kw
```

最贴自然人责任边界。

## 7. share 变量怎么做

建议同时做频率和占比。

频率：

```text
*_per10k = raw_count / risk_chars × 10000
```

占比：

```text
*_share = raw_count / (risk_specific_count + risk_action_count + risk_generic_count + 1)
```

或者更直接：

```text
risk_verif_share = verifiable_raw / (all_risk_keyword_raw + 1)
```

作用：

1. `per10k` 回答“可核验表达密度是否上升”；
2. `share` 回答“风险披露结构是否从泛化叙事转向可核验表达”。

主文优先使用：

```text
np_liability_risk_verif_share
risk_verif_no_policy_share
```

因为它们更贴“披露结构变化”。

## 8. 预期符号

如果理论是“PB 改变责任边界，促使高暴露企业更具体披露风险”，预期：

```text
PB × NPGuaranteeExposure_pre -> np_liability_risk_verif_share > 0
PB × NPGuaranteeExposure_pre -> risk_guarantee_pledge_kw > 0
PB × NPGuaranteeExposure_pre -> risk_legal_process_kw > 0
PB × NPGuaranteeExposure_pre -> risk_boilerplate_ratio < 0
```

如果暂时只有软 X：

```text
PB × natural_pre
PB × failure_cost_pre
PB × private_highlev_pre
PB × high_lev_pre
```

则解释要分开：

```text
natural_pre / failure_cost_pre:
  更接近自然人责任边界，但当前可能只推动 has_risk_text。

high_lev_pre:
  更接近债务压力/追偿价值暴露，不应叫自然人责任暴露。

private_highlev_pre:
  可作为自然人责任与债务压力的过渡代理，但仍不如自然人担保硬。
```

## 9. 推荐主表组合

如果后续补到硬 X：

```text
Table 1: X 覆盖率，NPGuaranteeExposure_pre / ControllerGuarantee_pre / Pledge_pre
Table 2: PB × NPGuaranteeExposure -> np_liability_risk_verif_share
Table 3: 组件 Y，担保质押、法律程序、债务逾期、自然人责任主体
Table 4: 模板化下降，risk_boilerplate_ratio
Table 5: 外部验证，真实担保/诉讼/质押/逾期事件
```

如果暂时只能用现有软 X：

```text
Table 1: PB × high_lev_pre -> risk_specificity_index / risk_quality_index
Table 2: PB × failure_cost_pre -> risk_debt_per10k / risk_verif_no_policy_share
Table 3: PB × natural_pre -> has_risk_text / np_liability_risk_verif_share
Table 4: 说明 high_lev_pre 是债务压力暴露，不叫自然人责任暴露
```

第二套只能作为试跑版，不建议作为最终投稿版。

## 10. 和现有第一版结果的衔接

现有第一版结果显示：

```text
PB × high_lev_pre -> risk_specificity_index / risk_quality_index 较稳
PB × natural_pre / failure_cost_pre -> has_risk_text 有信号但严格规格不稳
PB × failure_cost_pre / high_lev_pre -> risk_debt_per10k 有滞后信号
```

新 Y 的作用是把这三条统一到更清楚的披露结构：

```text
不是泛泛地说“风险披露质量提高”，
而是说“高责任/高追偿风险暴露企业披露了更多可核验的债务、担保、诉讼和自然人责任风险”。
```

## 12. 当前风险

1. 如果 X 仍然只有 `natural_pre` / `failure_cost_pre`，主线可能只能证明“更可能披露风险段”，不一定能证明“可核验性提高”。
2. 如果最强结果仍来自 `high_lev_pre`，论文就会滑向“债务压力与风险披露”，而不是纯自然人责任边界。
3. 风险段抽取必须人工校验，否则 `risk_verif` 可能混入财务附注、金融工具风险或公司治理段落。
4. 政策名词必须屏蔽，否则会出现机械相关。

## 13. 当前建议

可以推进这个 Y。

最推荐的题目方向是：

```text
自然人责任边界与企业可核验风险披露：
来自个人破产制度试点的证据
```

英文暂定：

```text
Natural-Person Liability Boundaries and Verifiable Risk Disclosure:
Evidence from Personal Bankruptcy Pilots
```

但正式推进前，必须补一个更硬的 X：

```text
自然人担保 / 个人连带保证 / 实控人股权质押
```

没有硬 X 时，这个 Y 可以先试跑，但不宜直接宣布主线已经闭合。
