# v15 测度升级说明

## 目的

`v15` 的重点不是继续堆稳健性，而是在现有双测度体系之外，把“数据要素利用”向更接近业务嵌入、链条完整和经营章节表述的方向推进半步。

## 保留不变的主设定

- 主因变量仍为 `PriceDelay`。
- `DU_kw` 仍是 baseline treatment。
- `DU_llm` 与 `DU_llm_lenstd` 仍是 semantic validation / depth measure。

## 新增增强测度

### 1. `DUevent`

- 定义：基于现有文本特征管线中的 `substantive_count` 构造，每万字标准化后形成 `DUevent`。
- 直觉：如果关键词周围上下文同时出现动作词、具体对象或数值信息，则更接近“数据被用于具体经营/治理场景”的表述。
- 结果：在 preferred lagged spec 下方向为负，但不显著；与 `DU_kw` 或 `GenericNarr` 联合进入后不稳定。
- 处理：不升主文主测度，仅作为补充尝试保留。

### 2. `DUchain_count`

- 定义：五个维度 `data_stock / data_dev / data_app / data_value / data_gov` 中被命中的维度数，范围为 `0-5`。
- 结果：`DUchain_count_{t-1} -> PriceDelay_t` 为负且在 5% 水平显著。
- 解释：更完整的数据利用链条与更快的价格发现相关。
- 处理：进入主文，作为“链条完整度”的支持性证据。

### 3. `DUclosedloop`

- 定义：当企业同时命中
  - 数据资源/存量类，
  - 应用/开发类，
  - 治理/价值实现类
  时取 `1`，否则为 `0`。
- 结果：单变量滞后规格显著为负；与 `GenericNarr` 联合进入后仍保持负向，达到 10% 水平。
- 解释：这是当前最贴近“闭环式数据利用表述”的增强指标。
- 处理：进入主文，作为最值得强调的增强测度。

### 4. `DUcore`

- 定义：以 `data_app + data_value + data_gov` 的强度构造窄口径核心指标。
- 结果：单变量滞后规格显著为负，但在与 `DU_kw` 或 `GenericNarr` 联合进入时不再稳健。
- 处理：保留为支持性材料，不替换 baseline。

### 5. `DUkw_mda`

- 定义：`MD&A` 章节内的关键词频率。
- 结果：单变量滞后规格显著为负，但联合回归中不再稳健。
- 解释：经营讨论章节中的数据利用披露具有定价含量，但更多体现为支持性而非增量性信息。
- 处理：进入主文的增强测度部分，但不进摘要核心结果层。

## 总结判断

- `v15` 至少有一个新增测度满足“显著为负且解释上更接近数据要素利用”的要求，具体是 `DUclosedloop`，`DUchain_count` 也提供方向一致的支持。
- `v15` 不能写成“新测度已经替代 `DU_kw`”。更稳妥的表述是：
  - 基准处理变量仍是 `DU_kw`；
  - 增强测度表明，资本市场确实会对更完整、更嵌入的数据利用表述作出更快反应；
  - 但这些增强测度主要承担构念升级的支持性角色，而不是新的 baseline。
