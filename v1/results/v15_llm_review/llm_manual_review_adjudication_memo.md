# LLM 边界样本裁决备忘

## 目的

- 汇总 29 条 `needs_adjudication = Y` 的边界样本。
- 提炼后续写入论文附录和重跑评分时应优先执行的裁决规则。

## 总体判断

- 这 29 条样本不是随机噪声，主要集中在少数稳定类型。
- 原归档分值偏高的样本，主要问题不是“看漏了应用场景”，而是把项目名、政策背景、释义条目和报表列示误当成了实质利用。
- 独立 Codex 的主要偏差，则集中在对技术描述和系统能力表述打分偏高，尤其容易把 `2` 打成 `3`。

## 四类高频边界情形

### 1. 名称、项目、补助、合同、任职信息

- 代表样本：`S031`、`S033`、`S038`、`S040`、`S041`
- 共同特征：关键词仅出现在项目名称、补助名称、合同标题、机构名称、董事任职或主体命名中。
- 裁决规则：除非同一窗口内能看到企业具体动作、用途或场景，否则一律按 `0` 分处理。

### 2. 政策背景、行业趋势、宏观规划

- 代表样本：`S032`、`S046`、`S058`、`S097`、`S106`、`S118`、`S119`
- 共同特征：文本讨论的是政策文件、产业趋势、市场空间或区域规划，不是企业自身如何利用数据。
- 裁决规则：宏观背景默认 `0` 分；只有当窗口明确转入企业自身业务动作时，才允许升分。

### 3. 释义、附注列示、报表项目、标准风险披露

- 代表样本：`S043`、`S048`、`S091`、`S093`、`S094`、`S095`、`S099`、`S101`、`S105`、`S110`、`S117`、`S120`
- 共同特征：关键词出现在术语定义、财务附注、报表行项目、公告标题或标准化风险管理说明中。
- 裁决规则：这类文本优先按 `0` 分；即便涉及“数据资源”“数据采集”“风险控制”等词，也不能仅凭名词本身上调评分。

### 4. 真正的边界应用样本

- 代表样本：`S063`、`S070`、`S078`、`S079`、`S107`
- 共同特征：已经出现企业层面的数据对象、技术动作或管理用途，但是否达到 `2/3` 分边界需要更严格判断。
- 裁决规则：
  - 有具体对象、动作和用途，但缺少闭环、系统嵌入或结果证据，判 `2` 分。
  - 同时出现数据对象、实施方式、经营或治理场景，并能看到较深层嵌入或价值实现，才判 `3` 分。
  - 若只是产品能力介绍或业务方向描述，最多 `1` 分。

## 后续用于重跑的收紧规则

- 规则 1：名称、标题、释义、报表列示、公告标题、政策口号，默认 `0` 分。
- 规则 2：宏观趋势或行业背景，默认 `0` 分，除非窗口内明确出现企业自身动作。
- 规则 3：`2` 分要求“企业层面 + 对象/动作 + 用途”；缺任一项就降到 `1` 分。
- 规则 4：`3` 分要求在 `2` 分基础上再看到闭环、嵌入、量化结果或价值实现证据。
- 规则 5：对技术方案类文本，不能只因出现算法、平台、系统就打高分，必须确认其落到企业经营、治理或决策场景。

## 对论文写作的含义

- 可以把人工复核结果写成“样本级 rubric 具有较高可复核性”。
- 不应再把企业-年份众数分值当作上下文级 gold label。
- 论文里应明确区分三层对象：上下文级评分、企业-年份聚合分值、人工复核样本。
